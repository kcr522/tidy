# 개발 기록 조각

PR마다 `docs/개발-기록.md`의 같은 줄(변경 기록 표 맨 아래, 마지막 갱신)을 고치면 PR끼리 충돌이 나요.
그래서 PR은 **이 폴더에 조각 파일 하나만** 더하고, `preview/all-features`에 합치면 GitHub Actions(`dev-record.yml`)가
조각을 개발 기록에 넣고, 마지막 갱신을 고치고, PDF를 다시 만든 뒤 조각 파일을 지워요.

파일 이름은 다른 PR과 겹치지 않게 브랜치 이름으로 (예: `project-thread-sersyy.md`).

```
## 6
| 2026-11-18 | #? | 기능 | 무엇을 했는지 | 검토 중 |

## 4-7
| 기능 이름 | 설명 | 🧪 | #? |

## 5-2
| 항목 | #? | 폰에서 확인할 것 |
```

- `## 6`, `## 4-7`, `## 5-2` 처럼 개발 기록의 섹션 번호를 쓰면, 그 섹션 첫 표 맨 아래에 줄이 붙어요.
- `#?`는 합친 PR 번호로 바뀌고, 6번 줄의 `검토 중`은 `합침`으로 바뀌어요.
- 이미 있는 줄의 상태를 바꾸거나 지우는 것만 `docs/개발-기록.md`를 직접 고쳐요. PDF는 PR에서 고치지 않아요.
- 직접 해 보기: `node scripts/doc-fragments.mjs 123` (123 = PR 번호)
