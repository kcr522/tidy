# 테스트 코드 작성 규칙 (어느 프로젝트에서나 쓰는 범용판)

어떤 앱·서버 프로젝트에서도 쓸 수 있게 정리한 규칙이에요. 사람이든 AI든 테스트를 새로 쓰거나 고칠 때 이 파일을 먼저 읽고 지켜요.
언어마다 표시 이름이 달라서, 맨 아래 "언어별 대응표"에서 내 언어 것을 찾아 쓰면 돼요.

---

## 1. 무엇을 시험하는지 문장으로 말하기
- 테스트마다 **사람이 읽는 설명 문장**을 붙인다. 형식은 **상황 → 기대 결과** 한 문장.
  - 좋음: "비밀번호가 8자보다 짧으면 가입을 거절한다"
  - 나쁨: "비밀번호 테스트", "test1"
- 버그를 고치며 넣은 테스트는 설명 끝에 이슈·PR 번호나 짧은 이유를 적는다: `— #123`.

## 2. 이름은 짧고 쉬운 영어로, 직역하면 바로 뜻이 통하게
- 함수·상수·변수 이름은 **짧고 쉬운 영어 단어**로 쓴다. 한국어로 직역했을 때 바로 뜻이 통해야 한다.
- 긴 문장 이름은 쓰지 않는다. 자세한 설명은 1번의 설명 문장에 쓴다.
  - 좋음: `rejectShortPassword`(짧은 비밀번호 거절), `freeShippingFrom50`(50부터 무료 배송), `MAX_PHOTOS`
  - 나쁨(너무 김): `rejectsPasswordWhenLengthIsLessThanEightCharacters`
  - 나쁨(뜻 모름): `test1`, `A`, `tmp`, `flag`, `doIt`, 팀만 아는 줄임말
- 줄임말은 **누구나 아는 것만, 한 파일 안에서 한 가지로** 쓴다(예: `lat`과 `latitude`를 섞지 않기).
- 참·거짓 기대값은 `isValid`, `isFree`처럼 "~인가"로 읽히게 쓴다.
- 이름을 바꿀 때는 그 자리 주석과 뜻이 어긋나지 않는지 확인한다.

## 3. 뜻이 안 보이는 값 쓰지 않기
- 맨 `true`/`false`, 맨 숫자를 함수에 바로 넣지 않는다. 이름 있는 변수나 상수로 먼저 만든다.
  - 나쁨: `search("cafe", false, 1000)`
  - 좋음: `openOnly = false`, `radius = 1000` 을 만든 뒤 `search("cafe", openOnly, radius)`
- 빈 값(`null`, `nil`, `undefined`)을 여러 개 넘길 때는 각각 이름을 붙이거나(`noMemo = null`) 도우미 함수로 감춘다.
- 기준값은 숫자를 두 번 쓰지 않고 상수 하나로 둔다: `MIN_PASSWORD = 8`.

## 4. 정상 값은 실제 있을 법한 값으로
- 망가뜨리지 않는 값은 **실제로 들어올 법한 값**을 쓴다. 예: 실제 도시 좌표, 실제 있을 법한 이메일·이름·가격.
- 이름도 그 값이 정상이라는 게 보이게 붙인다: `okEmail`, `okPrice`.

## 5. 한 테스트에서는 하나만 망가뜨리기
- 거절·오류를 시험할 때는 **딱 한 값만 이상하게** 넣고 나머지는 모두 정상으로 둔다. 그래야 무엇 때문에 실패했는지 바로 안다.
  - 좋음: `signUp(shortPassword, okEmail)` — 비밀번호만 이상함
  - 나쁨: 비밀번호도 짧고 이메일도 틀린 값 하나로 시험
- 다른 값이 결과에 끼어들지 않게 도우미 함수로 나머지를 고정한다: `onlyPassword(pw)`.

## 6. 한 테스트는 준비 → 실행 → 확인 세 덩어리
- 준비(Given) / 실행(When) / 확인(Then) 사이에 빈 줄을 하나씩 둔다.
- 실행은 되도록 한 줄. 결과는 이름 있는 변수에 담는다: `result = service.signUp(...)`.

## 7. 반복은 테스트 밖으로
- 같은 확인을 값만 바꿔 여러 번 할 때는 `for`나 복사 대신 **값 목록으로 여러 번 돌리는 기능**을 쓴다(대응표의 "여러 값으로 돌리기"). 결과 화면에 경우마다 따로 나온다.
- 긴 준비 코드는 이름 있는 도우미 함수로 뺀다.

## 8. 경계값은 안쪽·바깥쪽 짝으로
- 기준이 있으면 **딱 그 값(안쪽)**과 **바로 넘는 값(바깥쪽)**을 둘 다 시험한다.
  - 8자부터 허용 → 8자 통과, 7자 거절 / 사진 3장까지 → 3장 통과, 4장 거절 / 50부터 무료 → 50 무료, 49.99 유료.
- 두 값은 값 목록에 한 줄씩 나란히 둔다.

## 9. 주석은 "무엇을 확인하는지"를 쓰기
- 주석에는 코드를 다시 읽은 말이 아니라 **이 줄이 무엇을 확인하는지**를 쓴다.
  - 좋음: `// 두 번 불렀지만 API는 한 번만 불렸는지 확인`
  - 나쁨: `// assert 호출`
- 숫자에는 어디서 나온 값인지 적는다: `// 위도 0.001도 ≈ 111m`.
- 테스트 도구 표시의 뜻은 매번 주석으로 쓰지 말고, 팀 공부 문서나 아래 대응표에 한 번만 정리한다.

## 10. 가짜(mock)는 꼭 필요한 곳에만
- 외부 API·DB·결제처럼 느리거나 돈이 들거나 결과가 매번 다른 것만 가짜로 바꾼다.
- 가짜를 쓰면 "불렀는지"만 보지 말고 **내 코드가 만든 결과**를 확인한다. 필요하면 넘어간 값까지 본다.
- 시간은 진짜로 기다리지 않는다(`sleep` 금지). 시계를 주입하고 가짜 시계를 옮긴다.

## 11. 사람이 읽을 수 있게 (AI 같지 않게)
- 헷갈리는 기호·한 줄에 여러 일 하기를 피한다.
- 테스트 하나는 화면 한 번에 보이는 길이(대략 25줄)를 넘지 않게 한다.
- 지어낸 숫자를 쓰지 않는다. 예시 숫자는 문서·실제 데이터에서 가져오고 출처를 주석에 쓴다.

## 12. 내 담당만 고치기
- 다른 사람 담당 파일은 고치지 않는다. 필요하면 그 사람에게 부탁한다.

## 13. 고친 뒤 확인
- 고친 테스트 파일만 먼저 돌린다.
- 이름만 바꿨어도 JSON 칸 이름이나 문장 안 글자까지 바뀌지 않았는지 확인한다.
- 가능하면 코드를 일부러 한 곳 망가뜨려(예: `>=` → `>`) 테스트가 빨간불이 되는지 본다.

## 언어별 대응표

| 하는 일 | Java (JUnit 5 + AssertJ) | Kotlin (JUnit 5 / Kotest) | JavaScript·TypeScript (Jest·Vitest) | Python (pytest) |
|---|---|---|---|---|
| 테스트 표시 | `@Test` | `@Test` | `test(...)` / `it(...)` | `def test_...():` |
| 설명 문장(1번) | `@DisplayName("…")` | 백틱 이름 ``fun `짧은 비밀번호는 거절`()`` | `test("짧은 비밀번호는 거절", …)` | 함수 위 문서 문자열 `"""…"""` 또는 `ids=` |
| 여러 값으로 돌리기(7번) | `@ParameterizedTest` + `@CsvSource` | `@ParameterizedTest` + `@CsvSource` / Kotest `withData` | `test.each([...])` | `@pytest.mark.parametrize` |
| 테스트마다 먼저 준비 | `@BeforeEach` | `@BeforeEach` / `beforeTest` | `beforeEach(...)` | `@pytest.fixture` |
| 같은지 확인 | `assertThat(x).isEqualTo(y)` | `assertThat(x).isEqualTo(y)` / `x shouldBe y` | `expect(x).toBe(y)` | `assert x == y` |
| 오류가 나야 함 | `assertThatThrownBy(() -> …)` | `assertThrows<…> { … }` / `shouldThrow<…> { … }` | `expect(() => …).toThrow()` | `with pytest.raises(…):` |
| 가짜 만들기 | Mockito `mock(...)`, `when(...).thenReturn(...)` | MockK `mockk()`, `every { … } returns …` | `jest.fn()`, `vi.fn()` | `unittest.mock.Mock()` |
| 불렸는지 확인 | `verify(x, times(1))` | `verify(exactly = 1) { … }` | `expect(fn).toHaveBeenCalledTimes(1)` | `mock.assert_called_once()` |

표에 없는 언어·도구는 "하는 일" 칸을 보고 그 도구에서 같은 기능을 찾아 쓴다.

## 예시 (safe-route 서버에서 실제로 쓴 이름)
- `hotFrom33`(33도부터 폭염), `rejectNanLat`(NaN 위도 거절), `checkLocation(lat, lon)`(위치 검사), `noKeyNoGemini`(키 없으면 AI 안 부름)
- 경계값 짝: 33.0 폭염 / 32.9 아님, 위도 90 통과 / 90.1 거절
- 하나만 망가뜨리기: `checkLocation(nanLat, okLon)`

## Tidy 에서 쓰는 법

- 테스트 위치: `tests/unit/*.test.ts`, `tests/lib/*.test.ts` (Vitest, `npm test`). 안드로이드 기기 테스트는 `android/app/src/androidTest/`.
- 설명 문장은 한국어로 쓴다: `it('비밀번호가 7자면 쓸 수 없다', …)`. 이름(함수 · 상수 · 변수)은 짧은 영어.
- 여러 값으로 돌리기는 `it.each([...])`. 제목의 `%s` · `%i` · `%j` 는 값을 **앞에서부터 차례로** 쓰므로, 보여 줄 값을 앞에 두거나 `$0` · `$1` 처럼 번호로 고른다.
  - 예: `it.each([['딱 8자', 'abcd1234', true], ['7자', 'abc1234', false]])('글자 비밀번호가 %s 이면 쓸 수 있는가: $2', …)`
- 정상 값 도우미는 `okTx` · `okTodo` · `okBookmark` 처럼 `ok` 로 시작하고, 필요한 칸만 `over` 로 바꾼다.
- DB 테스트는 `fake-indexeddb/auto` + `new TidyDB('테스트마다 다른 이름')`, 끝나면 `db.delete()`.
- 가짜로 바꾸는 것: AI(Gemini · Groq), 인터넷(`fetch`), 폰 기능(Capacitor 플러그인). 우리 코드(저장소 · 계산)는 진짜로 돌린다.
- 코드 모양: 작은따옴표, 세미콜론 없음, 긴 줄. `npx prettier --write` 는 돌리지 않는다.
- 고친 뒤: `npx vitest run tests/unit/고친파일.test.ts` 와 `npm run lint`.
