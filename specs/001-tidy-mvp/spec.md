# Feature Specification: Tidy 1차 MVP (가계부 · 할 일 · 스크랩)

**Feature Branch**: `001-tidy-mvp`

**Created**: 2026-11-10

**Status**: Draft

**Input**: 「통합 라이프 앱 (가계부·할일·스크랩) 1주 완성을 위한 1차 MVP 요구사항 분석서 및 시스템 설계서」(`docs/MVP-요구사항-분석서.pdf`)를 보완. 추가 조건: 모바일 앱, 데스크톱 앱, 모바일 웹, 데스크톱 웹 네 환경에서 동작하고, 학교 서버에 연결하지 않고 기기 안에 데이터를 저장한다.

## 앱 이름

> **TIDY** (타이디 / TidyUp): '정돈된, 깔끔한'이라는 뜻으로, 일상 관리를 깔끔하게 해준다는 메시지를 담았다.

## 우선순위 표기

| 이 문서 | 원본 PDF | 뜻 |
|---|---|---|
| **P1** | P0 | 없으면 MVP가 아님. 반드시 1차에 완성 |
| **P2** | P1 | 1차에 포함. P1이 모두 끝난 뒤 구현 |
| **P3** | (추가) | 4개 환경 배포와 백업. 1차 마지막 날 구현 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 수입/지출 기록하고 이번 달 내역 보기 (Priority: P1)

사용자는 돈을 쓰거나 받을 때마다 금액, 날짜, 구분, 카테고리, 메모를 빠르게 기록한다. 가계부 화면에서는 선택한 달의 내역을 날짜별로 보고, 화면 위쪽에서 이번 달 총 수입, 총 지출, 잔액을 확인한다.

**Why this priority**: 가계부는 매일 쓰는 기능이고, 대시보드의 가계부 요약이 이 데이터를 사용한다.

**Independent Test**: 다른 기능 없이 가계부 화면만으로 내역을 추가, 수정, 삭제하고 월 합계가 맞는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 가계부가 비어 있을 때, **When** 지출 / 15,000원 / 오늘 / 식비 / "점심"을 저장하면, **Then** 오늘 날짜 아래에 내역이 보이고 이번 달 총 지출이 15,000원이 된다.
2. **Given** 이번 달 수입 3,500,000원, 지출 1,240,000원이 있을 때, **When** 가계부 화면을 열면, **Then** 위쪽에 수입 3,500,000원, 지출 1,240,000원, 잔액 2,260,000원이 보인다.
3. **Given** 금액 칸이 비어 있거나 0일 때, **When** 저장을 누르면, **Then** 저장되지 않고 금액 칸 아래에 "금액을 입력해 주세요" 안내가 보인다.
4. **Given** 내역이 있을 때, **When** 내역을 눌러 금액을 고치고 저장하면, **Then** 목록과 월 합계가 바로 바뀐다.
5. **Given** 내역이 있을 때, **When** 삭제를 누르고 확인 창에서 "삭제"를 누르면, **Then** 내역이 사라지고 월 합계가 다시 계산된다.
6. **Given** 11월 화면일 때, **When** 이전 달 버튼을 누르면, **Then** 10월 내역과 10월 합계가 보인다.

### User Story 2 - 할 일 등록하고 완료 체크하기 (Priority: P1)

사용자는 할 일의 내용, 마감일, 중요도를 적어 등록하고, 끝나면 체크박스를 눌러 완료 처리한다. '오늘' 탭에서는 오늘 해야 할 일만, '전체' 탭에서는 모든 할 일을 본다.

**Why this priority**: 할 일 관리는 세 가지 핵심 기능 중 하나이고, 스크랩 → 할 일 전환의 기반이다.

**Independent Test**: 할 일 화면만으로 추가, 수정, 완료 체크, 삭제, 탭 전환을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 할 일이 비어 있을 때, **When** "주간 업무 보고서 작성" / 마감 오늘 / 중요도 높음으로 저장하면, **Then** '오늘' 탭과 '전체' 탭 모두에 보인다.
2. **Given** 미완료 할 일이 있을 때, **When** 체크박스를 누르면, **Then** 제목에 취소선이 생기고 목록의 아래쪽(완료 영역)으로 이동한다. 다시 누르면 미완료로 돌아온다.
3. **Given** 마감일이 어제이고 미완료인 할 일이 있을 때, **When** '오늘' 탭을 열면, **Then** 그 할 일이 "기한 지남" 표시와 함께 맨 위에 보인다.
4. **Given** 마감일이 없는 할 일이 있을 때, **When** '오늘' 탭을 열면, **Then** 보이지 않고 '전체' 탭에서만 보인다.
5. **Given** 제목이 비어 있을 때, **When** 저장을 누르면, **Then** 저장되지 않고 "할 일을 입력해 주세요" 안내가 보인다.

### User Story 3 - 링크 스크랩하고 읽음 관리하기 (Priority: P1)

사용자는 나중에 볼 글이나 사이트의 URL, 제목, 메모를 저장한다. 스크랩은 카드 목록으로 보이고, 카드를 누르면 외부 브라우저에서 열린다. 읽음/안 읽음은 토글로 바꾼다.

**Why this priority**: 세 가지 핵심 기능 중 하나이고, 대시보드의 "읽지 않은 스크랩"이 이 데이터를 사용한다.

**Independent Test**: 스크랩 화면만으로 저장, 열기, 읽음 토글, 수정, 삭제를 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 스크랩이 비어 있을 때, **When** URL `react.dev/learn` / 제목 "React 성능 최적화 팁"을 저장하면, **Then** URL이 `https://react.dev/learn`으로 저장되고 맨 위에 "안 읽음" 카드로 보인다.
2. **Given** 제목을 비워 두고 저장하면, **Then** URL의 도메인(예: `react.dev`)이 제목으로 들어간다.
3. **Given** `abc` 처럼 주소 형식이 아닌 값을 입력하면, **When** 저장을 누르면, **Then** 저장되지 않고 "올바른 주소를 입력해 주세요" 안내가 보인다.
4. **Given** 카드가 있을 때, **When** 카드의 "열기"를 누르면, **Then** 웹에서는 새 탭, 앱에서는 기기의 기본 브라우저로 열리고 그 스크랩은 자동으로 "읽음"이 된다.
5. **Given** 읽음 카드가 있을 때, **When** 읽음 토글을 누르면, **Then** "안 읽음"으로 돌아간다.
6. **Given** 이미 저장된 URL을 다시 저장하려 하면, **Then** "이미 저장된 주소예요" 안내와 함께 저장할지 묻는다.

### User Story 4 - 대시보드에서 한눈에 보기 (Priority: P1)

앱을 열면 첫 화면인 대시보드에서 이번 달 가계부 요약, 오늘 할 일, 읽지 않은 스크랩을 한 번에 본다. 각 카드를 누르면 해당 화면으로 이동한다.

**Why this priority**: 세 기능을 하나의 앱으로 묶는 핵심 화면이다.

**Independent Test**: 각 기능에 데이터를 넣은 뒤 대시보드 숫자가 각 화면과 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이번 달 수입 3,500,000원, 지출 1,240,000원, 오늘 지출 32,000원일 때, **When** 대시보드를 열면, **Then** 가계부 카드에 수입, 지출, 오늘 지출, 사용률 "35% 사용"(지출 ÷ 수입, 반올림)이 보인다.
2. **Given** 오늘 할 일 5개 중 3개를 완료했을 때, **Then** 할 일 카드 제목에 "오늘 할 일 (3/5)"가 보이고, 카드 안에서 바로 체크할 수 있다.
3. **Given** 안 읽은 스크랩이 2개일 때, **Then** 스크랩 카드 제목에 "읽지 않은 스크랩 (2)"가 보이고 최근 것부터 최대 3개가 보인다.
4. **Given** 데이터가 하나도 없을 때, **Then** 각 카드에 "첫 내역을 기록해 보세요" 같은 안내와 추가 버튼이 보인다.
5. **Given** 이번 달 수입이 0원일 때, **Then** 사용률 자리에 "-"가 보인다.

---

### User Story 5 - 스크랩을 할 일로 전환하기 (Priority: P2)

사용자는 스크랩 카드의 [할 일로 전환] 버튼을 눌러, 그 글을 읽는 일을 날짜가 정해진 할 일로 등록한다. 할 일을 완료하면 스크랩도 읽음이 된다.

**Why this priority**: 원본 PDF의 연동 기능(P1). 세 기능이 따로 있을 때보다 실제 쓰임새가 커지지만, 각 기능이 먼저 있어야 한다.

**Independent Test**: 스크랩 하나를 할 일로 전환한 뒤, 할 일을 완료했을 때 스크랩이 읽음이 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 안 읽은 스크랩 "React 성능 최적화 팁"이 있을 때, **When** [할 일로 전환]을 누르고 날짜(기본값 오늘)를 고른 뒤 확인하면, **Then** 할 일 "읽기: React 성능 최적화 팁"이 생기고 스크랩 카드에 "할 일 등록됨" 표시가 생긴다.
2. **Given** 전환된 할 일이 있을 때, **When** 그 할 일을 완료 체크하면, **Then** 원래 스크랩이 "읽음"이 된다.
3. **Given** 이미 전환된 스크랩일 때, **Then** [할 일로 전환] 버튼 대신 "할 일 보기" 버튼이 보인다(스크랩 하나당 할 일 하나).
4. **Given** 전환된 할 일에서, **When** 링크 아이콘을 누르면, **Then** 원래 스크랩의 URL이 열린다.
5. **Given** 전환된 할 일을 삭제하면, **Then** 스크랩은 남아 있고 다시 [할 일로 전환]할 수 있다.

---

### User Story 6 - 카테고리와 필터로 편하게 쓰기 (Priority: P2)

가계부는 기본 카테고리를 드롭다운으로 고르고, 할 일은 '오늘'/'전체' 탭으로, 스크랩은 '전체'/'안 읽음' 필터로 나눠 본다.

**Why this priority**: 원본 PDF의 P1 기능. 없어도 쓸 수는 있지만 매일 쓰기에 불편하다.

**Independent Test**: 각 화면에서 카테고리 선택, 탭/필터 전환이 목록에 바로 반영되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 구분이 "지출"일 때, **When** 카테고리 드롭다운을 열면, **Then** 지출 카테고리 목록만 보인다. 구분을 "수입"으로 바꾸면 수입 카테고리 목록으로 바뀐다.
2. **Given** 가계부 목록에서, **When** 카테고리 필터에서 "식비"를 고르면, **Then** 식비 내역만 보이고 위쪽 합계도 식비 기준으로 바뀐다.
3. **Given** 스크랩 화면에서, **When** "안 읽음" 필터를 고르면, **Then** 읽지 않은 카드만 보인다.

---

### User Story 7 - 데이터 백업하고 네 가지 환경에서 쓰기 (Priority: P3)

사용자는 설정 화면에서 전체 데이터를 JSON 파일로 내보내고, 다른 기기에서 그 파일을 가져와 그대로 이어서 쓴다. Tidy는 폰 앱, 컴퓨터 앱, 폰 웹, 컴퓨터 웹에서 모두 같은 화면과 기능으로 열린다.

**Why this priority**: 서버가 없기 때문에 기기 사이 데이터 이동과 분실 대비는 백업 파일이 유일한 방법이다. 기능이 완성된 뒤 마지막 날 패키징한다.

**Independent Test**: 웹에서 데이터를 내보내고 앱에서 가져온 뒤, 모든 데이터가 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 데이터가 있을 때, **When** 설정 → "데이터 내보내기"를 누르면, **Then** `tidy-backup-2026-11-10.json` 파일이 저장된다.
2. **Given** 백업 파일이 있을 때, **When** "데이터 가져오기"로 파일을 고르고 "덮어쓰기"를 확인하면, **Then** 기존 데이터가 백업 내용으로 바뀐다.
3. **Given** Tidy 백업이 아닌 파일을 고르면, **Then** 아무것도 바뀌지 않고 "Tidy 백업 파일이 아니에요" 안내가 보인다.
4. **Given** 설정에서 "전체 데이터 삭제"를 누르면, **Then** 확인 문구 입력 후에만 삭제된다.
5. **Given** 폰(폭 360~430px)에서 열면, **Then** 아래쪽 탭 메뉴와 세로로 쌓인 대시보드 카드가 보인다. **Given** 컴퓨터(폭 1024px 이상)에서 열면, **Then** 왼쪽 메뉴와 가로 3칸 대시보드 카드가 보인다.
6. **Given** 인터넷을 끈 상태에서, **When** 앱을 열고 기록하면, **Then** 모든 기능이 정상 동작하고 다시 열어도 데이터가 남아 있다.

---

### Edge Cases

- **금액 범위**: 1원 미만, 소수, 999,999,999원 초과는 저장할 수 없다. 입력 중에는 천 단위 쉼표가 자동으로 붙는다.
- **미래 날짜 내역**: 저장할 수 있다. 해당 달 목록에 보이고 그 달 합계에 포함된다.
- **월이 바뀔 때**: 대시보드와 가계부의 "이번 달"은 기기의 현재 날짜 기준으로 다시 계산된다. 자정이 지나면 '오늘' 탭 기준도 바뀐다.
- **긴 텍스트**: 제목은 100자, 메모는 200자까지. 목록에서는 한 줄로 줄이고 "…"로 표시한다.
- **할 일 마감일이 지난 경우**: 미완료면 '오늘' 탭 맨 위에 "기한 지남"으로 보인다. 완료한 지난 할 일은 '오늘' 탭에 보이지 않는다.
- **오늘 완료한 할 일**: 마감일이 오늘이면 완료해도 '오늘' 탭에 남아(완료 영역) 진행률 (3/5)에 포함된다.
- **스크랩 삭제**: 그 스크랩에서 전환된 할 일은 남고, 연결만 끊긴다.
- **잘못된 URL 스킴**: `javascript:`, `file:` 등 http/https가 아닌 주소는 저장할 수 없다.
- **저장 실패**: 기기 저장 공간 부족 등으로 저장에 실패하면 입력한 내용을 지우지 않고 "저장하지 못했어요. 다시 시도해 주세요"를 보여 준다.
- **실수로 삭제**: 모든 삭제는 확인 창을 거친다.
- **백업 버전**: 백업 파일에는 앱 버전과 스키마 버전을 넣어, 나중 버전의 Tidy에서도 가져올 수 있게 한다.

## Requirements *(mandatory)*

### Functional Requirements

#### 공통 / 플랫폼

- **FR-001**: Tidy는 모바일 앱(Android, iOS), 데스크톱 앱(Windows, macOS), 모바일 웹, 데스크톱 웹에서 같은 기능으로 동작해야 한다.
- **FR-002**: 화면 폭 768px 미만에서는 아래쪽 탭 메뉴(대시보드, 가계부, 할 일, 스크랩, 설정)를, 768px 이상에서는 왼쪽 메뉴를 보여야 한다.
- **FR-003**: 모든 데이터는 기기 안의 로컬 DB에 저장해야 하며, 외부 서버로 데이터를 보내면 안 된다.
- **FR-004**: 로그인 없이 바로 사용할 수 있어야 한다.
- **FR-005**: 인터넷 연결 없이 모든 기능이 동작해야 한다(링크 열기 제외). 웹 버전은 한 번 연 뒤에는 오프라인에서도 열려야 한다.
- **FR-006**: 앱을 닫았다 열거나 기기를 재시작해도 데이터가 그대로 남아 있어야 한다.
- **FR-007**: 모든 삭제 동작은 확인 창을 거쳐야 한다.
- **FR-008**: 목록이 비어 있으면 안내 문구와 추가 버튼을 보여야 한다.
- **FR-009**: 금액은 천 단위 쉼표와 "원"을 붙여 표시하고, 날짜는 `11월 10일 (화)` 형식으로 표시해야 한다.

#### 가계부

- **FR-010**: 사용자는 구분(수입/지출), 금액, 날짜, 카테고리, 메모로 내역을 등록할 수 있어야 한다. 구분, 금액, 날짜, 카테고리는 필수, 메모는 선택이다.
- **FR-011**: 금액은 1 이상 999,999,999 이하의 정수만 허용해야 한다.
- **FR-012**: 날짜의 기본값은 오늘이고, 구분의 기본값은 지출이어야 한다.
- **FR-013**: 지출 카테고리는 식비, 교통, 쇼핑, 문화/여가, 주거/통신, 의료/건강, 교육, 기타를, 수입 카테고리는 월급, 용돈, 부수입, 기타를 기본 제공해야 한다.
- **FR-014**: 가계부 목록은 선택한 달의 내역을 최신 날짜부터, 같은 날짜는 최근 등록 순으로, 날짜별로 묶어 보여야 한다. 날짜 묶음마다 그날의 지출 합계를 표시한다.
- **FR-015**: 가계부 화면 위쪽에 선택한 달의 총 수입, 총 지출, 잔액(수입 − 지출)을 보여야 한다.
- **FR-016**: 이전 달/다음 달로 이동할 수 있어야 한다.
- **FR-017**: 내역을 눌러 수정하거나 삭제할 수 있어야 한다.
- **FR-018**: 카테고리로 목록을 거를 수 있어야 한다. (P2)

#### 할 일

- **FR-020**: 사용자는 제목(필수), 마감일(선택), 중요도(높음/보통/낮음, 기본값 보통)로 할 일을 등록할 수 있어야 한다.
- **FR-021**: 체크박스로 완료/미완료를 바꿀 수 있어야 하고, 완료한 할 일은 취소선과 함께 목록 아래쪽에 보여야 한다.
- **FR-022**: 할 일을 수정, 삭제할 수 있어야 한다.
- **FR-023**: '오늘' 탭은 마감일이 오늘인 할 일과, 마감일이 지났는데 미완료인 할 일("기한 지남" 표시)을 보여야 한다. (P2)
- **FR-024**: '전체' 탭은 모든 할 일을 미완료 → 완료 순으로, 그 안에서 마감일이 빠른 순(마감일 없는 것은 맨 뒤), 같으면 중요도 높은 순으로 보여야 한다.
- **FR-025**: 중요도는 색깔 표시(높음 빨강, 보통 주황, 낮음 회색)로 구분해야 한다.

#### 스크랩

- **FR-030**: 사용자는 URL(필수), 제목(선택), 메모(선택)로 스크랩을 저장할 수 있어야 한다.
- **FR-031**: URL에 `http://` 또는 `https://`가 없으면 `https://`를 붙여 저장하고, 그 밖의 스킴이나 주소 형식이 아닌 값은 거부해야 한다.
- **FR-032**: 제목이 비어 있으면 URL의 도메인을 제목으로 사용해야 한다.
- **FR-033**: 이미 저장된 URL이면 알려 주고, 사용자가 원할 때만 저장해야 한다.
- **FR-034**: 스크랩은 최근 저장 순의 카드 목록(제목, 도메인, 메모, 저장 날짜, 읽음 상태)으로 보여야 한다.
- **FR-035**: 카드의 "열기"를 누르면 외부 브라우저(웹은 새 탭)에서 열고, 그 스크랩을 읽음으로 바꿔야 한다. (P2)
- **FR-036**: 토글로 읽음/안 읽음을 바꿀 수 있어야 한다. (P2)
- **FR-037**: '전체'/'안 읽음' 필터를 제공해야 한다. (P2)
- **FR-038**: 스크랩을 수정, 삭제할 수 있어야 한다.

#### 연동: 스크랩 → 할 일 (P2)

- **FR-040**: 스크랩 카드의 [할 일로 전환]을 누르면 날짜를 고르는 창(기본값 오늘)을 띄우고, 확인하면 제목 "읽기: {스크랩 제목}", 선택한 마감일, 중요도 보통의 할 일을 만들어야 한다.
- **FR-041**: 스크랩 하나는 할 일 하나로만 전환할 수 있어야 한다(1:1). 전환된 스크랩에는 "할 일 등록됨" 표시와 "할 일 보기" 버튼을 보여야 한다.
- **FR-042**: 전환된 할 일을 완료하면 연결된 스크랩을 읽음으로 바꿔야 한다.
- **FR-043**: 전환된 할 일에는 링크 아이콘을 보여 주고, 누르면 원래 URL을 열어야 한다.
- **FR-044**: 스크랩이나 할 일 중 하나를 삭제해도 다른 하나는 남고 연결만 끊겨야 한다.

#### 대시보드

- **FR-050**: 앱을 열면 대시보드가 첫 화면이어야 한다.
- **FR-051**: 가계부 카드는 이번 달 총 수입, 총 지출, 오늘 지출, 사용률(총 지출 ÷ 총 수입 × 100, 반올림, 수입 0원이면 "-")과 사용률 막대를 보여야 한다.
- **FR-052**: 할 일 카드는 "오늘 할 일 (완료 수/전체 수)"와 오늘 할 일 목록(최대 5개)을 보여야 하고, 카드 안에서 바로 완료 체크할 수 있어야 한다.
- **FR-053**: 스크랩 카드는 "읽지 않은 스크랩 (개수)"와 최근 안 읽은 스크랩 최대 3개를 보여야 하고, 각 항목에 [할 일로 전환] 버튼을 보여야 한다.
- **FR-054**: 각 카드의 제목을 누르면 해당 화면으로 이동해야 한다.
- **FR-055**: 각 카드에 빠른 추가(+) 버튼을 두어, 대시보드에서 바로 등록할 수 있어야 한다.

#### 설정 / 백업 (P3)

- **FR-060**: 전체 데이터를 JSON 파일로 내보낼 수 있어야 한다. 파일에는 앱 버전, 스키마 버전, 내보낸 시각, 세 테이블의 모든 데이터가 들어간다.
- **FR-061**: JSON 백업 파일을 가져와 기존 데이터를 덮어쓸 수 있어야 한다. 형식이 맞지 않으면 아무것도 바꾸지 않아야 한다.
- **FR-062**: 확인 문구("삭제")를 입력해야만 전체 데이터를 지울 수 있어야 한다.
- **FR-063**: 설정 화면에 앱 버전과 "데이터는 이 기기에만 저장돼요. 기기를 바꾸기 전에 꼭 백업하세요" 안내를 보여야 한다.

### Key Entities *(include if feature involves data)*

- **Transaction (가계부 내역)**: 돈이 들어오거나 나간 한 건. 구분(수입/지출), 금액, 카테고리, 날짜, 메모, 생성/수정 시각을 가진다.
- **Todo (할 일)**: 해야 할 일 하나. 제목, 완료 여부, 완료 시각, 마감일, 중요도, 생성/수정 시각, 그리고 전환된 경우 원래 스크랩(Bookmark) 참조를 가진다.
- **Bookmark (스크랩)**: 저장한 링크 하나. URL, 제목, 메모, 읽음 여부, 생성/수정 시각을 가진다. 할 일 하나와 1:1로 연결될 수 있다.

자세한 필드와 규칙은 `data-model.md`를 따른다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 지출 한 건을 대시보드에서 기록하는 데 10초 이내(탭 4번 이내)가 걸린다.
- **SC-002**: 저장, 체크, 삭제 같은 동작 후 화면 반영이 0.5초 안에 끝난다.
- **SC-003**: 앱/웹을 연 뒤 대시보드가 2초 안에 보인다(내역 1,000건 기준).
- **SC-004**: 네 가지 환경(폰 앱, 컴퓨터 앱, 폰 웹, 컴퓨터 웹)에서 Acceptance Scenario를 모두 통과한다.
- **SC-005**: 인터넷을 끈 상태에서도 링크 열기를 뺀 모든 Acceptance Scenario를 통과한다.
- **SC-006**: 내보낸 백업 파일을 다른 환경에서 가져오면 데이터 건수와 내용이 100% 같다.
- **SC-007**: 대시보드 숫자(월 수입/지출, 오늘 할 일 진행률, 안 읽은 스크랩 수)가 각 화면의 실제 데이터와 항상 일치한다.
- **SC-008**: 7일 동안 개발자 본인이 매일 실제로 사용하면서 데이터가 사라지거나 잘못 계산되는 일이 없다.

## 1차 범위 밖 (Out of Scope)

다음 기능은 아이디어로 기록만 하고 1차에서는 만들지 않는다.

- 가계부 ↔ 할 일 연동 (예: "마트 장보기" 완료 시 식비 지출 기록). 원본 PDF ERD에 "참조/완료시 연동"으로만 적혀 있어 2차에서 구체화한다.
- 기기 사이 자동 동기화, 로그인, 클라우드 저장
- 사용자 정의 카테고리, 예산 설정, 지출 그래프/통계
- 반복 할 일, 알림(푸시), 하위 할 일
- 스크랩 미리보기 이미지 자동 가져오기, 태그, 폴더, 검색
- 다크 모드, 다국어

## Assumptions

- 사용자는 개발자 본인 한 명이고, 한 기기에서 주로 쓰며 필요할 때 백업 파일로 옮긴다.
- 통화는 원(KRW) 하나이고 소수 금액은 없다.
- "오늘"과 "이번 달"은 기기의 현지 시간대를 기준으로 한다.
- 마감일은 날짜만 정하고 시각은 정하지 않는다.
- 웹 버전의 데이터는 브라우저별로 따로 저장된다(크롬에서 쓴 데이터가 사파리에 보이지 않음). 브라우저 데이터를 지우면 함께 지워지므로 백업을 안내한다.
- iOS 앱 빌드에는 Mac과 Xcode가, 앱스토어 배포에는 개발자 계정이 필요하다. 1차에서는 스토어 배포 없이 개인 기기 설치까지만 한다.
