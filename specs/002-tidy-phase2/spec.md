# Feature Specification: Tidy 2차 추가 기능 (캘린더 · 구글 로그인 · AI 내역 자동 입력)

**Feature Branch**: `002-tidy-phase2`

**Created**: 2026-11-10

**Status**: Draft (1차 MVP 완성 후 착수)

**Input**: User description: "로그인 기능도 있어야 할 것 같은데 귀찮으니까 그냥 구글 연동 로그인으로 되도록 하고, 사용한 금액 은행앱에서 캡쳐한 거나 잔액 그런 거 인식해서 자동으로 AI가 내역 가계부에 써 주는 기능도 있었으면 좋겠고, 투두 리스트와 함께 캘린더 기능도 있으면 좋겠는데, 캘린더에서 날짜 누르면 그때 뭘 해야 할지 보이는 거랑 눌러서 거기에 투두 할 수 있는 기능"

> **선행 조건**: [1차 MVP](../001-tidy-mvp/spec.md)가 완성되어 있어야 한다. 2차 기능은 1차의 테이블(Transaction, Todo, Bookmark)과 화면을 그대로 확장한다.

## ⚠️ 1차 원칙과 충돌하는 부분

[헌법](../../.specify/memory/constitution.md)의 **원칙 II "서버 없이, 기기 안에서"**는 로그인, 외부 서버 통신을 1차 범위에서 뺐다. 2차 기능 중 두 가지는 이 원칙을 바꿔야 한다.

| 기능 | 왜 서버가 필요한가 | 원칙 변경 필요 |
|---|---|---|
| 캘린더 | 필요 없음. 기기 안 데이터만 사용 | ❌ 없음 |
| 구글 로그인 | 구글 계정 확인 + 로그인한 사람의 데이터를 기기 사이에서 공유하려면 온라인 저장소가 필요 | ✅ 필요 |
| AI 캡처 인식 | AI 모델에 이미지를 보내야 하고, AI API 키를 앱 안에 넣으면 누구나 빼 갈 수 있어 중간 서버(서버리스 함수)가 필요 | ✅ 필요 |

**제안하는 원칙 개정 (2차 착수 전에 헌법 v2.0.0으로 반영)**

> II. **오프라인 우선, 서버는 선택** — 학교 서버는 쓰지 않는다. 모든 기능은 로그인 없이도 기기 안에서 동작해야 하고(1차 그대로), 로그인과 AI 기능은 사용자가 켰을 때만 외부 서비스(Firebase, AI API)를 사용한다. 인터넷이 끊겨도 기록은 기기에 저장되고, 다시 연결되면 동기화한다.

## 우선순위와 권장 순서

| 순서 | User Story | 우선순위 | 난이도 | 이유 |
|---|---|---|---|---|
| 1 | 캘린더 (US1, US2) | **P1** | 중 | 서버 없이 바로 만들 수 있고, 1차 할 일 데이터를 그대로 사용 |
| 2 | 구글 로그인 + 동기화 (US3) | **P2** | 상 | AI 기능의 사용량 관리와 개인 데이터 보호에 로그인이 먼저 필요 |
| 3 | AI 캡처 인식 (US4, US5) | **P3** | 상 | 로그인과 서버리스 함수 위에 만든다 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 캘린더에서 날짜별 할 일 보기 (Priority: P1)

사용자는 캘린더 화면에서 한 달을 한눈에 보고, 할 일이 있는 날짜에 표시(점)를 본다. 날짜를 누르면 그날 마감인 할 일 목록이 아래에(컴퓨터에서는 옆에) 나온다.

**Why this priority**: 할 일을 날짜로 계획하는 기본 화면이고, 서버 없이 1차 데이터만으로 만들 수 있다.

**Independent Test**: 마감일이 다른 할 일 몇 개를 만든 뒤 캘린더에서 날짜를 눌러 목록이 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 11월 15일 마감 할 일 2개가 있을 때, **When** 캘린더를 열면, **Then** 15일 칸에 점이 표시된다(완료 안 한 할 일이 있으면 진한 점, 모두 완료면 흐린 점).
2. **Given** 캘린더에서, **When** 15일을 누르면, **Then** "11월 15일 (토)" 제목과 함께 그날 할 일 2개가 보이고, 바로 완료 체크할 수 있다.
3. **Given** 오늘 날짜는, **Then** 캘린더에서 동그라미로 강조된다.
4. **Given** 11월 화면에서, **When** 좌우로 넘기거나 화살표를 누르면, **Then** 이전/다음 달로 이동한다. "오늘" 버튼을 누르면 이번 달로 돌아온다.
5. **Given** 할 일이 없는 날짜를 누르면, **Then** "이날은 할 일이 없어요" 안내와 추가 버튼이 보인다.

### User Story 2 - 캘린더에서 날짜를 눌러 할 일 추가하기 (Priority: P1)

사용자는 캘린더에서 날짜를 고른 뒤 바로 그 날짜가 마감일로 들어간 할 일을 추가한다.

**Why this priority**: 사용자가 요청한 핵심 동작. US1과 함께 있어야 캘린더가 쓸모 있다.

**Independent Test**: 캘린더에서 날짜를 골라 할 일을 추가한 뒤, 할 일 화면에서도 같은 마감일로 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 캘린더에서 11월 20일을 고른 상태에서, **When** "+ 할 일 추가"를 누르면, **Then** 마감일이 11월 20일로 채워진 할 일 입력 창이 열린다.
2. **Given** 저장하면, **Then** 20일 칸에 점이 생기고, 할 일 화면의 '전체' 탭에도 보인다.
3. **Given** 컴퓨터 화면에서, **When** 날짜 칸을 두 번 누르면, **Then** 바로 할 일 입력 창이 열린다.
4. **Given** 할 일을 다른 날짜로 옮기고 싶을 때, **When** 할 일을 눌러 마감일을 바꾸면, **Then** 캘린더 표시도 새 날짜로 옮겨진다. (드래그로 옮기기는 3차)

### User Story 3 - 구글 계정으로 로그인하고 기기 사이 동기화 (Priority: P2)

사용자는 설정에서 "Google로 로그인"을 눌러 로그인한다. 로그인하면 폰, 컴퓨터, 웹 어디서든 같은 데이터를 본다. 로그인하지 않아도 1차처럼 기기 안에서 그대로 쓸 수 있다.

**Why this priority**: 회원가입 없이 구글 계정 하나로 로그인하고, 네 가지 환경의 데이터를 자동으로 맞춘다. 1차의 백업 파일 옮기기를 대신한다.

**Independent Test**: 웹에서 로그인해 내역을 기록하고, 폰 앱에서 같은 계정으로 로그인했을 때 같은 내역이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 상태에서, **When** 설정 → "Google로 로그인"을 누르고 계정을 고르면, **Then** 설정에 내 이름, 프로필 사진, 이메일이 보인다.
2. **Given** 로그인하지 않고 쓰던 데이터가 기기에 있을 때 처음 로그인하면, **Then** "이 기기의 데이터를 계정에 올릴까요?"를 묻고, 확인하면 계정 데이터와 합친다.
3. **Given** 웹과 폰 앱에 같은 계정으로 로그인한 상태에서, **When** 웹에서 할 일을 추가하면, **Then** 5초 안에 폰 앱에도 나타난다.
4. **Given** 인터넷이 끊긴 상태에서 기록하면, **Then** 기기에 저장되고 "동기화 대기" 표시가 보이며, 다시 연결되면 자동으로 올라간다.
5. **Given** 로그인한 상태에서, **When** "로그아웃"을 누르면, **Then** "이 기기에서 데이터를 지울까요, 남길까요?"를 묻는다.
6. **Given** 로그인한 사용자 A의 데이터는, **Then** 다른 사용자 B가 절대 읽거나 고칠 수 없다.

### User Story 4 - 은행 앱 캡처로 가계부 자동 입력 (Priority: P3)

사용자는 은행/카드 앱의 결제 알림이나 거래 내역 화면을 캡처해서 Tidy에 올린다. AI가 날짜, 금액, 가게 이름, 수입/지출을 읽어 가계부 입력 칸을 자동으로 채운다. 사용자는 확인하고 저장한다.

**Why this priority**: 매번 손으로 입력하는 수고를 크게 줄이지만, 로그인과 서버리스 함수가 먼저 있어야 한다.

**Independent Test**: 거래 3건이 보이는 은행 앱 캡처를 올려, 3건이 맞는 금액과 날짜로 입력 후보에 뜨는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가계부 화면에서, **When** "📷 캡처로 입력" → 이미지를 고르면, **Then** "읽는 중…" 표시 후 10초 안에 인식된 내역 목록이 나온다.
2. **Given** 캡처에 거래가 3건 있으면, **Then** 3건이 각각 구분, 금액, 날짜, 가게 이름(메모), 추천 카테고리가 채워진 카드로 보이고, 저장할 것을 체크(기본 전부 체크)할 수 있다.
3. **Given** AI가 "스타벅스 강남점 6,500원"을 읽으면, **Then** 카테고리는 "식비"로 추천되고 사용자가 바꿀 수 있다.
4. **Given** 사용자가 금액을 고치고 "저장"을 누르면, **Then** 고친 값으로 가계부에 저장된다. 확인 없이 자동 저장되는 일은 없다.
5. **Given** 이미 같은 날짜, 같은 금액, 같은 가게 내역이 있으면, **Then** 그 카드에 "이미 있는 내역일 수 있어요" 표시가 붙고 기본 체크가 해제된다.
6. **Given** 은행 화면이 아닌 사진(풍경 등)을 올리면, **Then** "거래 내역을 찾지 못했어요" 안내가 나온다.
7. **Given** 폰에서는, **When** 다른 앱(갤러리, 은행 앱)의 "공유" → Tidy를 고르면, **Then** 바로 캡처 인식 화면이 열린다.

### User Story 5 - 잔액 캡처로 실제 잔액 확인 (Priority: P3)

사용자는 은행 앱의 잔액 화면을 캡처해서 올린다. AI가 계좌 잔액을 읽어 저장하고, Tidy에 기록된 내역으로 계산한 잔액과 차이가 나면 알려 준다.

**Why this priority**: 빠뜨린 내역을 찾게 도와주지만, US4가 먼저 있어야 한다.

**Independent Test**: 잔액 화면 캡처를 올려 잔액이 정확히 읽히고 저장되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** "잔액 1,234,560원"이 보이는 캡처를 올리면, **Then** 은행 이름(읽히면), 잔액, 날짜가 채워진 확인 창이 나오고 저장할 수 있다.
2. **Given** 잔액이 저장되어 있으면, **Then** 대시보드 가계부 카드에 "실제 잔액 1,234,560원 (11/10 기준)"이 보인다.
3. **Given** 지난 잔액 기록 이후 Tidy 내역으로 계산한 잔액과 새 잔액이 다르면, **Then** "기록되지 않은 내역이 약 23,000원 있어요" 안내와 "지출로 추가" 버튼이 보인다.

---

### Edge Cases

- **캘린더 – 마감일 없는 할 일**: 캘린더에 보이지 않는다(할 일 화면 '전체' 탭에서만).
- **캘린더 – 한 날짜에 할 일이 많을 때**: 칸에는 점 하나(또는 개수 숫자)만, 목록은 스크롤.
- **캘린더 – 주 시작 요일**: 일요일 시작(설정에서 월요일로 변경 가능).
- **로그인 – 팝업 차단/취소**: 로그인 창을 닫으면 아무것도 바뀌지 않고 로그인 전 상태 유지.
- **로그인 – 두 기기에서 같은 항목을 동시에 수정**: 나중에 수정한 것이 남는다(`updatedAt` 기준).
- **로그인 – 삭제 동기화**: 한 기기에서 지운 항목은 다른 기기에서도 지워진다(삭제 표시 후 30일 뒤 완전 삭제).
- **AI – 개인정보**: 캡처에 계좌번호, 이름 등이 있을 수 있다. 이미지는 인식에만 쓰고 서버/AI 쪽에 저장하지 않는다. 처음 사용할 때 이 내용을 안내하고 동의를 받는다.
- **AI – 잘못 읽음**: 모든 인식 결과는 사용자가 확인한 뒤에만 저장한다.
- **AI – 인터넷 없음**: "인터넷 연결이 필요해요" 안내, 손으로 입력하는 기능은 그대로.
- **AI – 사용량**: 비용 관리를 위해 계정당 하루 인식 횟수를 제한한다(예: 30회). 넘으면 안내.
- **AI – 이미지 크기**: 큰 이미지는 앱에서 줄여서(긴 변 1600px) 보낸다. 10MB 넘는 파일은 거부.
- **AI – 외화/할부**: 외화 금액은 원화로 바꾸지 않고 메모에 원래 금액을 남기고 "확인 필요" 표시. 할부는 결제된 금액 기준.

## Requirements *(mandatory)*

### Functional Requirements

#### 캘린더 (P1)

- **FR-101**: 메뉴에 "캘린더"를 추가해야 한다(폰 아래 탭: 대시보드, 가계부, 할 일·캘린더, 스크랩, 설정 — 할 일 화면 안에 "목록/캘린더" 전환으로 넣는다).
- **FR-102**: 월 단위 캘린더를 보여 주고, 이전/다음 달 이동, "오늘" 버튼, 폰에서 좌우 스와이프를 지원해야 한다.
- **FR-103**: 마감일이 있는 할 일이 있는 날짜에 표시(미완료 있음: 진한 점, 모두 완료: 흐린 점)를 해야 한다.
- **FR-104**: 날짜를 누르면 그날 마감인 할 일 목록을 보여 주고, 목록에서 완료 체크, 수정, 삭제가 가능해야 한다.
- **FR-105**: 선택한 날짜에서 "할 일 추가"를 누르면 마감일이 그 날짜로 채워진 입력 창을 열어야 한다.
- **FR-106**: 오늘 날짜를 강조하고, 지난 날짜의 미완료 할 일은 빨간 점으로 표시해야 한다.
- **FR-107**: (선택) 날짜를 누르면 그날의 지출 합계도 함께 보여 줄 수 있다.

#### 구글 로그인 + 동기화 (P2)

- **FR-110**: 설정 화면에서 "Google로 로그인"을 제공해야 한다. 별도 회원가입, 비밀번호는 없다.
- **FR-111**: 로그인은 선택이어야 한다. 로그인하지 않아도 1차의 모든 기능이 기기 안에서 동작해야 한다.
- **FR-112**: 로그인하면 Transaction, Todo, Bookmark 데이터를 사용자 계정의 온라인 저장소와 동기화해야 한다.
- **FR-113**: 오프라인에서 기록한 내용은 기기에 먼저 저장하고, 연결되면 자동으로 동기화해야 한다.
- **FR-114**: 첫 로그인 시 기기의 기존 데이터를 계정에 올릴지 물어야 한다.
- **FR-115**: 사용자는 자신의 데이터만 읽고 쓸 수 있어야 한다(저장소 보안 규칙으로 강제).
- **FR-116**: 로그인은 네 가지 환경(폰 앱, 컴퓨터 앱, 폰 웹, 컴퓨터 웹) 모두에서 동작해야 한다.
- **FR-117**: 설정에서 로그아웃과 "계정 데이터 전체 삭제(탈퇴)"를 제공해야 한다.
- **FR-118**: 1차의 JSON 백업 내보내기/가져오기는 그대로 유지해야 한다.

#### AI 캡처 인식 (P3)

- **FR-120**: 가계부 화면과 대시보드에 "📷 캡처로 입력" 버튼을 두어, 이미지를 고르거나(갤러리/파일) 붙여넣기(컴퓨터 Ctrl+V)로 올릴 수 있어야 한다.
- **FR-121**: AI는 이미지에서 거래마다 날짜, 시각(있으면), 금액, 수입/지출, 가게/상대 이름, 추천 카테고리를 읽어 구조화된 결과(JSON)로 돌려줘야 한다.
- **FR-122**: 인식 결과는 수정 가능한 입력 후보 카드로 보여 주고, 사용자가 확인한 것만 저장해야 한다.
- **FR-123**: 이미 있는 내역과 날짜, 금액, 가게 이름이 같으면 중복 가능성을 표시해야 한다.
- **FR-124**: 잔액 화면 캡처에서 은행 이름, 잔액, 기준 날짜를 읽어 잔액 기록으로 저장할 수 있어야 한다.
- **FR-125**: 마지막 잔액 기록과 Tidy 내역 합계를 비교해 차이를 알려 줘야 한다.
- **FR-126**: AI API 키는 앱 코드에 넣지 않고, 로그인한 사용자만 호출할 수 있는 서버리스 함수에서만 사용해야 한다.
- **FR-127**: 이미지는 인식이 끝나면 저장하지 않고 버려야 한다. 처음 사용할 때 이 내용을 안내하고 동의를 받아야 한다.
- **FR-128**: 계정당 하루 인식 횟수 제한을 두어야 한다.
- **FR-129**: 폰 앱은 다른 앱의 "공유" 메뉴로 이미지를 받아 인식 화면을 열 수 있어야 한다.

### Key Entities *(include if feature involves data)*

- **User (사용자)** *(신규)*: 구글 계정으로 로그인한 사람. 구글 ID, 이름, 이메일, 프로필 사진, 첫 로그인 시각. 모든 데이터의 주인.
- **Transaction / Todo / Bookmark** *(확장)*: 1차 필드에 `userId`(로그인 시), `deletedAt`(동기화용 삭제 표시)을 추가. Transaction에는 `source`(`MANUAL` | `AI_CAPTURE`)를 추가해 AI로 들어온 내역을 구분.
- **BalanceSnapshot (잔액 기록)** *(신규)*: 특정 시점의 실제 계좌 잔액. 은행 이름, 잔액, 기준 날짜, 입력 방식(직접/AI), 생성 시각.
- **CalendarDay**: 저장하지 않음. Todo의 `dueDate`로 계산해서 보여 준다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-101**: 캘린더에서 날짜를 눌러 할 일을 추가하는 데 탭 3번, 10초 이내.
- **SC-102**: 캘린더 화면이 1초 안에 열린다(할 일 1,000개 기준).
- **SC-103**: 구글 로그인이 버튼을 누른 뒤 15초 안에 끝난다(계정 선택 포함).
- **SC-104**: 한 기기에서 바꾼 내용이 다른 기기에 5초 안에 나타난다(둘 다 온라인일 때).
- **SC-105**: 은행 앱 캡처 하나를 올려 저장까지 30초 이내(손 입력은 건당 약 20초).
- **SC-106**: 은행 앱 거래 캡처 20장 테스트에서 금액, 날짜 인식 정확도 95% 이상.
- **SC-107**: 로그인하지 않은 상태로도 1차의 모든 Acceptance Scenario를 그대로 통과한다.

## 기술 방향 (계획 단계에서 확정)

| 기능 | 추천 | 대안 |
|---|---|---|
| 캘린더 | 직접 만든 월 달력 컴포넌트 (date-fns) | react-day-picker 등 라이브러리 |
| 구글 로그인 | **Firebase Authentication** (Google 제공자). 웹은 팝업, 폰 앱은 `@capacitor-firebase/authentication`, 컴퓨터 앱(PWA 설치)은 웹과 같은 팝업 방식 | Supabase Auth |
| 동기화 저장소 | **Cloud Firestore** (오프라인 저장 지원, 사용자별 보안 규칙). 기존 Dexie는 오프라인 캐시로 유지 | Dexie Cloud, Supabase(PostgreSQL) |
| AI 인식 | **Firebase Cloud Functions**에서 Claude 비전 모델 API 호출, 응답은 JSON 형식으로 받기 | 기기 안 OCR(Tesseract.js) + 규칙 — 무료지만 정확도 낮음 |
| 비용 | Firebase 무료 요금제(Spark)로 시작. 단, Cloud Functions는 종량제(Blaze) 요금제가 필요하고, AI API는 사용량만큼 비용 발생 | |

## 1차 → 2차 데이터 이전

- 1차 사용자는 로그인 없이 계속 쓸 수 있다.
- 처음 로그인할 때 기기 안 Dexie 데이터를 Firestore로 올린다(FR-114).
- 로컬 DB 스키마는 Dexie `version(2)`로 올려 `userId`, `deletedAt`, `source` 필드와 `balanceSnapshots` 테이블을 추가한다. 기존 데이터는 그대로 유지된다.

## 2차 범위 밖 (3차 이후)

- 은행/카드사 계좌 직접 연동(오픈뱅킹, 마이데이터) — 금융 규제와 인증이 필요
- 결제 문자/알림 자동 읽기(Android 알림 접근 권한)
- 구글 캘린더 연동(가져오기/내보내기)
- 캘린더에서 할 일 드래그로 날짜 옮기기, 주간/일간 보기, 반복 일정
- 여러 사람이 함께 쓰는 공유 가계부
- 카카오/애플 로그인

## Assumptions

- 사용자는 구글 계정이 있다.
- 2차는 1차 MVP를 실제로 써 본 뒤에 시작하며, 그 경험에 따라 우선순위를 다시 조정할 수 있다.
- AI 인식은 한국 은행/카드 앱의 한국어 화면을 기준으로 한다.
- Firebase 프로젝트와 AI API 키는 개발자 본인 계정으로 만들고, 키는 GitHub에 올리지 않는다(`.env`, Firebase 환경 설정 사용).
- iOS 앱에서 구글 로그인을 쓰려면 Apple 개발자 설정이 추가로 필요하다.
